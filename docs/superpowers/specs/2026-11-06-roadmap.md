# Roadmap after 0.6

Written 2026-11-06, after the README, screenshots and demo video work. Revised 2026-11-07. Each release gets its own design before it's built.

The goal is to reach more dbt users. They will arrive through launch posts that link to ctediff.dev. Nobody has asked for another warehouse yet, so BigQuery is the only one added before the post. It is about a day of work and can be tested on the free BigQuery sandbox.

| Release | Theme | Effort |
|---|---|---|
| 0.7 | Smoother first run, and a plain message on unsupported warehouses | about 1 day |
| 0.8 | BigQuery | about 1 day, plus a check on the sandbox |
| site | Launch-ready landing page | about 1 day |
| post | Launch post (dbt Slack, LinkedIn, Reddit) | drafts |
| 0.9 | Review a PR in one pass | about 2 days |
| 0.10 | Read results faster | about 2 days |

First run goes first. The README and video bring new installs, and today the main buttons are hidden in diffs by default (`docs/usage.md`, "Open a comparison"). That is where new users drop off. The landing page and the post come after 0.7 and 0.8, so the people the post brings in get a fixed first run and can compare on Snowflake, BigQuery or DuckDB.

## 0.7: Smoother first run

- The first time a SQL diff opens, offer to turn on `diffEditor.codeLens` with one click.
- **CTE Diff: Check Setup** checks the dbt path and version, the project, and the profile and target (`dbt debug`). Results show in the panel with fixes, and it runs on its own after a failure.
- A getting-started walkthrough (`contributes.walkthroughs`), with images from `npm run capture`.
- Honest states:
  - A cancel is not "dbt failed" (`src/dbt.ts`, the `Cancelled` error).
  - Errors from before dbt runs go in the panel, not toasts (`src/extension.ts`, `guard`).
  - The panel's heading shows the files, the target and the run time.
  - **Choose dbt Project** changes the project picked for the session (`src/extension.ts`, `projectFor`).
- `examples/duckdb` becomes the site's jaffle sample (`web/sample.ts`) with a ready "after" file, so the example matches the video.
- Consider distinct lens wording: dbt Power User's lenses ("Preview CTE | … | Execute") share the line with "▶ Preview".
- The sidebar's welcome view names all three ways in: the title bar, Compare Files, and paste.
- A plain message on unsupported warehouses. Today a Compare on Redshift, Databricks or Postgres runs the Snowflake SQL and shows a raw warehouse error.
  - Snowflake gets its own branch in `byAdapter` (`src/query.ts`). The last branch raises a dbt compiler error that names `target.type`.
  - The panel shows "Compare runs on Snowflake and DuckDB. Preview works on <type>."
  - It adds a link to open an issue titled "Compare on <type>". With no telemetry, those issues decide which warehouse comes next.
- The unreleased 0.6.3 entry in `CHANGELOG.md` folds into 0.7.

## 0.8: BigQuery

- `byAdapter` becomes a map of duckdb, bigquery and snowflake that emits `if` / `elif` / `else`. `forAdapter` and its callers (`web/sample.ts`, `web/playground.ts`, `test/query.test.ts`) read the new shape.
- The BigQuery branch:
  - Row to JSON: `to_json_string(to_json(__t, stringify_wide_numbers => true))`.
  - `except distinct`, because bare `except` is invalid in BigQuery.
  - The counts: `to_json_string(json_object(...))`. BigQuery has no `::varchar`.
- The parser (`src/cte.ts`) reads backtick names and `#` comments. DuckDB uses `#1` for positional references, so this release's design decides how far `#` goes.
- Check on the BigQuery sandbox with dbt-bigquery:
  - `TO_JSON` sorts keys. If it doesn't, sort them by hand, as the DuckDB branch does.
  - Reordered columns don't show as differences.
  - `NULL` and a missing column still differ.
  - Bytes billed per Compare. BigQuery runs a CTE again for each reference, and each side is referenced about three times. If the bill multiplies, rewrite the query to read each side once. Otherwise say so in the FAQ.
- The name becomes **CTE Diff for dbt**. The description, keywords, README, install, FAQ and comparison pages name BigQuery. The playground's SQL toggle gets a BigQuery tab.

## Site: launch-ready landing page

The site stays on MkDocs Material. This is a pass, not a redesign. Judge the look again afterwards and redesign only if it still reads generic.

- Social card: OG and Twitter tags and a 1200×630 image, through an `extrahead` block in `overrides/main.html`. Today a shared link shows no preview.
- Dark mode: Material's `slate` scheme with a toggle, and the tokens in `docs/stylesheets/extra.css` redefined for it.
- Self-hosted Geist instead of the render-blocking `@import` in `extra.css`.
- Hero: the value in one line, naming BigQuery, and a demo window shorter than today's fixed 720px.
- Phones:
  - The demo keeps its diff, which `home.css` hides below 720px.
  - The header keeps its Install button.
  - The demo's 760px breakpoint matches the CSS's 720px.
- Weight:
  - The 4.1 MB video loads lazily.
  - The demo and playground scripts load only on their own pages.
  - Remove unused images after checking that `scripts/capture.ts` doesn't write them.
- Clean-up:
  - The dev notes in `docs/index.md` and `docs/playground.md`, which search indexes.
  - The doubled page title.
  - Missing footer links.
  - The leftover "qdbd's header" comment.
  - The avatar hotlinked from github.com.

## 0.9: Review a PR in one pass

- **⇄ Compare all** in the sidebar: one `dbt show` returns per-CTE counts for every changed and affected CTE. One query, not one per CTE.
- Each sidebar row then carries its data verdict ("3 of 12 rows gone"). That makes the landing page's ledger real.
- A summary table in the panel. Each row opens that CTE's full comparison through `command:` links, so the webview still needs no scripts.
- **Copy as Markdown**, for pasting into the PR comment.
- Re-record one clip (`npm run capture`) and add the scene to the demo video.

## 0.10: Read results faster

- An interactive table: a nonce CSP enables webview scripts, which `src/panel.ts` blocks today. Sort, filter, a frozen key column, and long cells truncated with the full value on hover.
- Per-column change counts, numeric deltas, and a "changed columns only" toggle.
- An id column picker. Rows pair up in TypeScript (`readComparison` in `src/query.ts`), so re-pairing needs no new query.
- Copy a cell, row or table as CSV or Markdown.
- Duplicate-aware compare: `EXCEPT` is distinct, so duplicates from a bad join hide today.

```
order_payments · 3 changed rows               key: order_id ▾    ⌕ filter     Copy ▾
changed columns: [total_amount ×3]            ☑ changed columns only
      order_id   total_amount
  −         14          32.00
  +         14          24.00    −8.00
```

## Later

- Redshift, Databricks and Postgres, each once someone asks through the 0.7 issue link. Redshift needs a different comparison: it has no way to turn `*` into JSON (see `docs/adr/0001-compare-rows-as-sorted-json.md`).
- Dev vs prod: `--defer --state`, and comparing across targets.
- Scale: cut a long result by key rather than by JSON text, and cap the rows the panel renders.
- Parser: say where parsing stopped; read `//` as an operator.
- CI runs the comparison SQL on DuckDB for real; the publish job runs the tests; Open VSX publishes from CI.
