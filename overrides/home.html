See what a dbt change did to the data, one CTE at a time.

Open a model’s diff in VS Code and click above any CTE. Preview its rows on either side, or compare both sides and get the rows only one of them returns. Queries run through dbt show, so Jinja, refs and your Snowflake profile work as in a real run.

A diff shows what the SQL changed. It can’t show what the data did.

A one-line filter in an upstream CTE moves the numbers in every CTE that reads it. The diff shows one green line. To see the effect, you copy both versions into a worksheet, render the Jinja by hand, and write the except yourself, CTE by CTE.

cte-diff does that from the diff editor. It marks the CTEs that read a changed one, runs the same CTE on both sides, and lists the rows only one side returns.

Try it on two queries

Edit either side. The extension’s own parser, running in your browser, marks each CTE and writes the SQL the extension would send through dbt show. Nothing reaches a warehouse here: rows need dbt and your profile.

    Read how to use it

    Rows compare by column name, in one query

    Each side’s CTE becomes select * from that CTE, keeping the CTEs before it. Every row turns into JSON with object_construct_keep_null(*), so a renamed or dropped column shows up as a difference instead of an error.

    except runs both ways, with each side’s row count, in a single query, on Snowflake or DuckDB. It compares distinct rows: if only duplicates changed, the counts differ but no rows are listed.

    Read how the comparison works

    with __l as (select to_json(object_construct_keep_null(*)) as __row
             from (-- the left side's CTE)),
     __r as (select to_json(object_construct_keep_null(*)) as __row
             from (-- the right side's CTE)),
     __only_l as (select __row from __l except select __row from __r),
     __only_r as (select __row from __r except select __row from __l)
select -- row counts, then the rows of __only_l and __only_r

    Before you install

    dbt
    dbt Fusion, or dbt-core 1.5 or later, with a working profile. Key-pair, SSO and password logins all work. A project .env is loaded first.
    Warehouse
    Previews work on any warehouse dbt supports. Comparisons run on Snowflake and DuckDB.
    Workspace
    A trusted one: dbt runs the project’s macros.
