A VS Code extension for dbt. Open source under Apache 2.0, version {{ config.extra.version }}

See what a dbt change did to the data, one CTE at a time.

Open a model’s diff in VS Code and click above any CTE. Preview its rows on either side, or compare both sides and get the rows only one of them returns. Queries run through dbt show, so Jinja, refs and your warehouse profile work as in a real run.

A diff shows what the SQL changed. It can’t show what the data did.

Checking it by hand means copying both versions into a worksheet, rendering the Jinja and writing the except yourself, CTE by CTE.

cte-diff marks every CTE that reads a changed one, and runs any CTE on both sides: from a diff, the sidebar, two SQL files, or another branch.

Preview your working tree

-- models/orders.sql, HEAD ↔ working tree
payments as (
    select * from {{ "{{" }} ref('stg_payments') {{ "}}" }}
    where status = 'success'
),
  1. Click orders.sql in Source Control. HEAD opens on the left, your edits on the right.
  2. Click ▶ Preview above payments on the left: 12 rows.
  3. Click it on the right: 9 rows. Or ⇄ Compare sides for the rows only one side has.
// settings.json: VS Code hides lenses in diffs by default.
// CTE Diff offers to set this the first time a SQL diff opens.
"diffEditor.codeLens": true

Without it, ⇄ Compare a CTE… in the editor’s title bar and the sidebar work the same.

▶ Preview runs one CTE through dbt show, on either side of the diff. dbt Power User’s Execute CTE only runs on the right.

Compare two files

-- Old: the logic in production
payments as (
    select * from {{ "{{" }} ref('stg_payments') {{ "}}" }}
),
-- New: your copy
payments as (
    select * from {{ "{{" }} ref('stg_payments') {{ "}}" }}
    where status = 'success'
),
  1. In the sidebar’s Compare Files, hover orders_v1.sql and click ← to make it Old.
  2. Hover orders_v2.sql and click → to make it New.
  3. Click Open the diff, then ⇄ Compare sides above payments.

Two paths, not two versions of one: a dev copy against prod’s, or a rewrite against the original. No file at all? CTE Diff: New Comparison takes two pasted queries.

Check against another branch

  1. On dev, hover orders.sql in Compare Files and click ⑂. Or click Compare with Branch… in the sidebar’s title bar.
  2. Pick qa. orders.sql (qa) ↔ orders.sql opens.
  3. Click ⇄ Compare sides above order_payments.

Local branches, then remote ones. The branch you’re on and tags are left out.

  • The left side is the branch’s latest commit, not the commit your branch forked from.
  • The right side is your working tree, uncommitted edits included.
  • Both run on your one dbt target, so the comparison shows what the SQL changed, not what QA’s tables hold.

Working on dev and merging into qa? See what the merge does to the data before you open the pull request.

How ⇄ Compare sides finds the rows that changed

It runs the CTE on both sides in one query, through dbt show, and keeps only the rows one side has. Here it is on order_payments from the demo.

  1. 1

    Run the CTE on both sides

    The old and the new order_payments, each with the CTEs it reads.

    − old
    order_idtotal_amount
    1118
    1432
    5245
    8718
    + new
    order_idtotal_amount
    1118
    1424
    5230
    879
  2. 2

    Match rows by column name

    Each row becomes text keyed by column name. Column order doesn’t matter, and a renamed or dropped column shows up as a difference, not an error.

    • −{"order_id":11,"total_amount":18}
    • −{"order_id":14,"total_amount":32}
    • −{"order_id":52,"total_amount":45}
    • −{"order_id":87,"total_amount":18}
    • +{"order_id":11,"total_amount":18}
    • +{"order_id":14,"total_amount":24}
    • +{"order_id":52,"total_amount":30}
    • +{"order_id":87,"total_amount":9}
  3. 3

    Keep what only one side has

    Rows on both sides drop out. What’s left is the change: each old row above its new one, matched on order_id.

    order_idtotal_amount
    3 changed rows
    −1432
    +1424
    −5245
    +5230
    −8718
    +879

BigQuery, DuckDB, Redshift or Snowflake, one query, one dbt show run. It compares distinct rows: if only duplicates changed, the row counts differ but no rows are listed (Redshift has no row counts). Read how the comparison works

Before you install

dbt
dbt Fusion, or dbt-core 1.5 or later, with a working profile. Key-pair, SSO and password logins all work. A project .env is loaded first.
Warehouse
Previews work on any warehouse dbt supports. Comparisons run on BigQuery, DuckDB, Redshift and Snowflake.
Workspace
A trusted one: dbt runs the project’s macros.
